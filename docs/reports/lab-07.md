## 1. Цель работы
Создать в папке `/backend` того же репозитория каркас серверного приложения на ASP.NET Core Web API с портом `5000`, подключить Swagger для режима `Development`, реализовать служебные маршруты `/health` (`liveness`) и `/info`, а также подготовить слои `Controllers`, `Services`, `Models`, `Data` с внедрением зависимостей (DI).

## 2. Реализованная структура `/backend` и DI

1. **Сетевая конфигурация (`backend/Properties/launchSettings.json`):**
   * В профиле `http` зафиксирован порт `5000` (`http://localhost:5000`), среда `ASPNETCORE_ENVIRONMENT=Development`.
2. **Служебные маршруты (`backend/Program.cs`):**
   * `GET /health` возвращает `200 OK` с текстом `"ok"` (не принимает поля заявки).
   * `GET /info` возвращает JSON со сведениями о приложении (`app: "ElectronicDeaneryApi"`, `environment: "Development"`, `version: "0.1.0-lab07"`).
   * Включены `UseSwagger()` и `UseSwaggerUI()` для среды `Development`.
3. **Слои приложения и DI:**
   * `Controllers/AppealsController.cs` — контроллер-заготовка с тестовым `GET /api/appeals`, получающий зависимость через конструктор.
   * `Services/IAppealService.cs`, `Services/AppealService.cs` — интерфейс и сервис-заготовка.
   * `Models/.gitkeep` и `Data/.gitkeep` — зарезервированные директории под модели и доступ к PostgreSQL в ЛР8–ЛР10.

> **Принцип DI:** Сервис зарегистрирован через DI (`AddSingleton<IAppealService, AppealService>()`), чтобы контроллер не создавал реализацию через `new`.

## 5. Ответы на контрольные вопросы защиты

1. **Чем C# отличается от ASP.NET Core?**  
   *Ответ:* C# — это язык программирования, на котором написаны файлы `.cs`. .NET — платформа исполнения и SDK (`dotnet run`). ASP.NET Core — веб-фреймворк поверх .NET, который принимает HTTP-запросы, строит конвейер middleware, маршрутизирует вызовы в контроллеры и формирует HTTP-ответы.

2. **Зачем нужен DI, если можно написать `new`?**  
   *Ответ:* Если контроллер сам создаёт `new AppealService()`, он жёстко привязывается к конкретной реализации. При регистрации через DI (`AddSingleton<IAppealService, AppealService>`) контроллер зависит только от интерфейса `IAppealService` — в ЛР10 можно будет легко подменить сервис в памяти на сервис с PostgreSQL, не переписывая код контроллера.

3. **Что доказывает успешный `/health`?**  
   *Ответ:* Ответ `200` от `GET /health` доказывает только доступность процесса сервера (`liveness`) — то, что приложение ASP.NET Core запустилось и обрабатывает HTTP-запросы. Он ничего не говорит о наличии бизнес-операций или сохранении данных в БД.

4. **Почему создание заявки ещё не готово?**  
   *Ответ:* По плану курса ЛР7 посвящена только каркасу Web API, DI, портам и служебным проверкам. Реализация `POST /api/appeals`, валидация модели и смена статусов относятся к следующей лабораторной работе (ЛР8).
