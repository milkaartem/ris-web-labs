## 1. Цель работы
Связать форму создания обращения на маршруте `/new` (`AppealNew.vue`) с общим реактивным массивом в `src/appealsStore.js`: настроить двустороннюю привязку (`v-model`, `v-model.number`), предотвратить перезагрузку страницы (`@submit.prevent`), реализовать клиентскую валидацию и автоматический возврат на список `/` после добавления записи со статусом `New`.

## 2. Реализованная логика (`<script setup>` и `<template>`)

1. **Хранилище в памяти (`frontend/src/appealsStore.js`):**
   * Хранит реактивный массив `items`, учебный счётчик `nextId` (начинается с `5`) и функцию `addItem({ title, serviceTypeId, description })`.
   * Каждая новая запись получает уникальный в рамках сессии `id`, временный номер `TMP-${id}` и фиксированный начальный статус `'New'`.

2. **Форма создания (`frontend/src/pages/AppealNew.vue`):**
   * Реактивное состояние `form` связано с полями формы через `v-model="form.title"`, `v-model.number="form.serviceTypeId"`, `v-model="form.description"`.
   * Клиентская валидация в `onCreate()` перед добавлением:
     - `title` после `.trim()` — от 5 до 80 символов;
     - `serviceTypeId` — целое число больше 0 (`Number.isInteger(serviceTypeId) && serviceTypeId > 0`);
     - `description` после `.trim()` — от 10 до 500 символов.
   * При ошибке выводится сообщение рядом с соответствующим полем, а вызов `addItem` блокируется оператором `return`.
   * После успешного добавления ошибки и поля очищаются, и выполняется переход `router.push('/')`.

### Таблица «script / template»

| Задача | В `<script setup>` | В `<template>` |
|--------|--------------------|----------------|
| Объявить форму и список | `const form = ref({ title: '', serviceTypeId: 0, description: '' })`, `import { addItem } from '../appealsStore.js'` | — |
| Прочитать / связать поля | `form.value.title.trim()`, `form.value.serviceTypeId` | `v-model="form.title"`, `v-model.number="form.serviceTypeId"`, `v-model="form.description"` |
| Отправить форму без перезагрузки | `function onCreate() { ... }` | `<form novalidate @submit.prevent="onCreate">` |

| Уйти на список после успеха | `router.push('/')` | — |
| Вывод списка с безопасным экранированием | `export const items = ref([...])` | `v-for="item in items" :key="item.id"`, `{{ item.title }}` |

## 5. Ответы на контрольные вопросы защиты

1. **Зачем нужен `.prevent`?**  
   *Ответ:* Модификатор `.prevent` в `@submit.prevent="onCreate"` вызывает `event.preventDefault()` и отменяет стандартное поведение браузера при отправке HTML-формы — полную перезагрузку страницы. Благодаря этому выполняется наш JavaScript-обработчик `onCreate`, а состояние Vue в памяти не сбрасывается.

2. **Почему у `serviceTypeId` нужен `.number`?**  
   *Ответ:* По умолчанию браузер возвращает значение из `<input>` как строку (даже при `type="number"`, например `"2"`). Модификатор `v-model.number` автоматически приводит введённое значение к числовому типу `number`, который требуется проверкой `Number.isInteger(...)` и будущим серверным контрактом ASP.NET Core.

3. **Где хранится массив?**  
   *Ответ:* Единый реактивный массив `items` (вместе со счётчиком `nextId` и функцией `addItem`) хранится в одном общем модуле `frontend/src/appealsStore.js`. Страница создания вызывает `addItem(...)`, а страница списка передаёт `items` в компонент таблицы через props.

4. **Почему F5 очищает новые записи?**  
   *Ответ:* Массив `items` живёт только в оперативной памяти текущей вкладки браузера. При обновлении страницы (`F5`) JavaScript-приложение запускается заново с исходными 4 тестовыми элементами — это ожидаемое поведение до подключения серверного API и базы данных PostgreSQL.
