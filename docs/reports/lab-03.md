## 2. Реализованный функционал и экраны

В файле `frontend/src/App.vue` реализовано переключение трёх экранов через реактивную переменную `screen` (`'list' | 'new' | 'login'`) и директивы `v-if` / `v-else-if` / `v-else`:

1. **Экран «Список» (`screen === 'list'`):**
   * Семантическая таблица `<table>`, заполняемая из реактивного массива `items` через `v-for="item in items" :key="item.id"`.
   * Содержит 4 тестовых обращения с четырьмя обязательными статусами курса: `New`, `InProgress`, `Closed`, `Cancelled`.
   * Выводимые поля: регистрационный номер (`number`), заголовок (`title`), числовой код категории услуги (`serviceTypeId`) и статус (`status`). Пользовательский текст выводится через `{{ ... }}`.

2. **Экран «Создать» (`screen === 'new'`):**
   * Форма `<form @submit.prevent="handleCreateSubmit">`, предотвращающая перезагрузку страницы.
   * Критерий 1 ЛР1 закрывают поля `title`, `serviceTypeId`, `description` на форме создания обращения:
     - `title` (текстовое поле, подпись «Тема, 5–80 символов», `autofocus` при открытии формы);
     - `serviceTypeId` (числовое поле `type="number"`, ссылка на справочник услуг деканата);
     - `description` (многострочное поле `<textarea>`, подпись «Описание, 10–500 символов»).

3. **Экран «Вход» (`screen === 'login'`):**
   * Заготовка формы авторизации с полями `login` и `password` (тип `password`), связанными с элементами `<label>`.

## 4. Ответы на контрольные вопросы защиты

1. **Зачем нужен Vite, если браузер уже показывает HTML?**  
   *Ответ:* Браузер понимает только обычный HTML, CSS и стандартный JavaScript, но не умеет напрямую исполнять однофайловые компоненты `.vue` (`<template>`, `<script setup>`, `<style scoped>`). Vite выступает сборщиком и dev-сервером: он компилирует `.vue`-файлы «на лету» в валидный для браузера JS/CSS и мгновенно обновляет страницу при правках (HMR) на порту `5173`.

2. **Чем `v-for` лучше трёх строк, скопированных вручную?**  
   *Ответ:* Директива `v-for` декларативно связывает разметку с массивом данных. Когда в следующих лабораторных данные придут с сервера (`GET /api/appeals`), таблица автоматически отрисует любое количество строк без дублирования HTML-кода, а атрибут `:key="item.id"` позволяет Vue точно отслеживать и обновлять каждую строку.

3. **Зачем полю `label`?**  
   *Ответ:* Элемент `<label for="...">` семантически связывает текстовую подпись с конкретным элементом ввода по его `id`. Это улучшает доступность (скринридеры озвучивают назначение поля) и удобство работы (клик по подписи автоматически переводит фокус внутрь соответствующего поля ввода).

4. **Почему `node_modules` не кладут в Git?**  
   *Ответ:* Папка `node_modules` содержит тысячи файлов сторонних библиотек весом в десятки или сотни мегабайт. Хранить их в истории Git нецелесообразно: точный список и версии зависимостей уже зафиксированы в `package.json` и `package-lock.json`. Любой разработчик (или сосед) восстанавливает папку локально одной командой `npm install`.
