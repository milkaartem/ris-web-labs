## 1. Матрица обязательных критериев приёмки ЛР1

В таблице ниже показана прямая связь обязательных критериев приёмки (формата Дано / Когда / Тогда) с моделью данных и серверным REST API:

| № критерия | Критерий приёмки из ЛР1 | Затрагиваемые сущности и поля | Выполняемый HTTP-запрос | Ожидаемый результат и код ответа |
|:----------:|-------------------------|--------------------------------|-------------------------|-----------------------------------|
| **Критерий 1** | **Создать объект:** Студент заполняет заголовок (5–80 симв.), выбирает услугу из справочника (`serviceTypeId` > 0), вводит описание (10–500 симв.) и нажимает «Создать». | `Appeal`<br>• `title`<br>• `serviceTypeId`<br>• `description`<br>• `number`<br>• `status` | `POST /api/appeals` | HTTP `201 Created`<br>Запись создана, присвоен уникальный номер `number` («ОБР-XXXX»), установлен статус `New`, `assigneeUserId = null`. |
| **Критерий 2** | **Назначить исполнителя:** Заместитель декана выбирает ответственного сотрудника отдельным действием (не меняя статус). | `Appeal`<br>• `assigneeUserId` | `PATCH /api/appeals/{id}/assignee` | HTTP `200 OK`<br>Поле `assigneeUserId` обновлено; статус остаётся неизменным (`New`). |
| **Критерий 3** | **В работу:** Назначенный сотрудник деканата переводит закреплённое за ним обращение в статус `InProgress`. Чужой пользователь статус не двигает. | `Appeal`<br>• `status`<br>• `assigneeUserId` | `PATCH /api/appeals/{id}/status` | HTTP `200 OK`<br>Статус изменён на `InProgress`. При запросе от стороннего пользователя сервер возвращает `403 Forbidden` / `409 Conflict`. |

## 2. Полная матрица функциональных требований (ФТ-1 — ФТ-13)

| Код ФТ | Формулировка функционального требования из ТЗ | Сущность и поля модели данных | Эндпоинт и метод API | Поведение и валидация |
|:------:|------------------------------------------------|-------------------------------|----------------------|-----------------------|
| **ФТ-1** | Просмотр студентом списка поданных обращений | `Appeal` (`createdByUserId`, `status`, `number`) | `GET /api/appeals?myOnly=true` | Фильтрация по `created_by_user_id = CurrentUserId`. |
| **ФТ-2** | Форма создания нового обращения с обязательными полями | `Appeal` (`title`, `serviceTypeId`, `description`) | `POST /api/appeals` | Валидация: `title` [5..80], `description` [10..500], `serviceTypeId` существование в справочнике. |
| **ФТ-3** | Автоматическая генерация `id`, `number` и статуса `New` | `Appeal` (`id`, `number`, `status`) | `POST /api/appeals` | Генерация сервером; клиенту запрещено передавать эти поля. |
| **ФТ-4** | *Запрет:* Студент не может менять статус и назначать людей | `Appeal` (`assigneeUserId`, `status`) | `PATCH .../assignee`<br>`PATCH .../status` | Ограничение на уровне ролевой авторизации (только роли `ViceDean`, `Staff`). |
| **ФТ-5** | Заместитель декана просматривает общий реестр обращений | `Appeal`, `ServiceType`, `User` | `GET /api/appeals` | Выборка всех обращений с поддержкой фильтров по статусам и категориям. |
| **ФТ-6** | Назначение ответственного сотрудника на обращение `New` | `Appeal` (`assigneeUserId`) | `PATCH /api/appeals/{id}/assignee` | Запись `assigneeUserId` сотрудника с ролью `Staff`. |
| **ФТ-7** | Разделение операций: статус при назначении не меняется | `Appeal` (`status`) | `PATCH /api/appeals/{id}/assignee` | Эндпоинт модифицирует исключительно `assigneeUserId`, поле `status` не затрагивается. |
| **ФТ-8** | Сотрудник деканата видит список закреплённых обращений | `Appeal` (`assigneeUserId`) | `GET /api/appeals?assignedToMe=true` | Фильтрация по `assignee_user_id = CurrentUserId`. |
| **ФТ-9** | Сотрудник деканата переводит своё обращение `New` $\to$ `InProgress` | `Appeal` (`status`) | `PATCH /api/appeals/{id}/status` | Проверка `assignee_user_id == CurrentUserId`, смена статуса на `InProgress`. |
| **ФТ-10** | *Запрет:* Сотрудник не может менять чужие обращения | `Appeal` (`assigneeUserId`) | `PATCH /api/appeals/{id}/status` | Проверка принадлежности; при несовпадении — код `409 Conflict`. |
| **ФТ-11** | Сотрудник переводит обращение `InProgress` $\to$ `Closed` | `Appeal` (`status`) | `PATCH /api/appeals/{id}/status` | Перевод в статус `Closed` с фиксацией `updatedAt`. |
| **ФТ-12** | Перевод обращения в статус `Cancelled` с фиксацией причины | `Appeal` (`status`, `description`) | `PATCH /api/appeals/{id}/status` | Доступно Замдекана и назначенному сотруднику. |
| **ФТ-13** | *Запрет:* Недопустимые переходы графа состояний | `Appeal` (`status`) | `PATCH /api/appeals/{id}/status` | Серверная валидация графа переходов (запрет `Closed` $\to$ `New` и т.д.). |
