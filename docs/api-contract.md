## 1. Общие правила REST API

- **Базовый URL:** `http://localhost:5000/api`
- **Формат данных:** `application/json; charset=utf-8`
- **Коды статусов жизненного цикла в API и БД:** строго фиксированные строки `New`, `InProgress`, `Closed`, `Cancelled`.
- **Запрет метода DELETE:** удаление записей не поддерживается. Неактуальное или некорректное обращение переводится в статус `Cancelled` («Отклонено»).
- **Разделение модификаций:** изменение назначенного исполнителя (`/assignee`) и смена статуса (`/status`) разнесены в **два независимых PATCH-эндпоинта**.
- **RESTful-маршрутизация:** никаких служебных глаголов в путях (запрещены пути вроде `/api/appeals/create` или `/api/appeals/update`). Действие определяет HTTP-метод.

| `GET /api/appeals` | Получить список обращений | Все роли (с фильтрацией) | — (параметры строки: `?status=&serviceTypeId=`) | `200 OK` (массив или `[]`) | — |

## 3. Детальное описание и примеры запросов / ответов

### 3.1. `GET /api/appeals` — Список обращений
Возвращает список обращений. Если записей в базе данных ещё нет — возвращается HTTP `200 OK` и **пустой массив `[]`** (код `404` не используется).

**Пример ответа (`200 OK`):**
```json
[
  {
    "id": 1,
    "number": "ОБР-2026-0001",
    "title": "Выдача справки об обучении за 3 семестр",
    "serviceTypeId": 1,
    "status": "InProgress",
    "createdByUserId": 15,
    "assigneeUserId": 3,
    "createdAt": "2026-10-12T10:15:00Z"
  }
]
```

---

### 3.2. `GET /api/appeals/{id}` — Одно обращение по ID
Возвращает детальную карточку конкретного обращения.

**Пример успешного ответа (`200 OK`):**
```json
{
  "id": 1,
  "number": "ОБР-2026-0001",
  "title": "Выдача справки об обучении за 3 семестр",
  "description": "Справка необходима для предоставления в пенсионный фонд.",
  "serviceTypeId": 1,
  "status": "InProgress",
  "createdByUserId": 15,
  "assigneeUserId": 3,
  "createdAt": "2026-10-12T10:15:00Z",
  "updatedAt": "2026-10-12T10:30:00Z"
}
```

**Пример ошибки (`404 Not Found`):**
```json
{
  "error": "NotFound",
  "message": "Обращение с идентификатором 999 не найдено."
}
```

---

### 3.3. `POST /api/appeals` — Создание нового обращения
Студент отправляет только содержательные данные. Поля `id`, `number`, `status` (`New`), `assigneeUserId` (`null`), `createdByUserId` и временные метки **заполняются исключительно сервером**.

**Пример тела запроса:**
```json
{
  "title": "Заявление на перевод в другую группу",
  "serviceTypeId": 2,
  "description": "Прошу рассмотреть возможность перевода в группу ТРИС-1-23 по семейным обстоятельствам."
}
```

**Пример успешного ответа (`201 Created`):**
```json
{
  "id": 2,
  "number": "ОБР-2026-0002",
  "title": "Заявление на перевод в другую группу",
  "serviceTypeId": 2,
  "description": "Прошу рассмотреть возможность перевода в группу ТРИС-1-23 по семейным обстоятельствам.",
  "status": "New",
  "createdByUserId": 15,
  "assigneeUserId": null,
  "createdAt": "2026-10-12T12:00:00Z",
  "updatedAt": "2026-10-12T12:00:00Z"
}
```

**Пример ошибки валидации (`400 Bad Request`):**
```json
{
  "error": "ValidationError",
  "errors": {
    "title": ["Длина заголовка должна составлять от 5 до 80 символов."],
    "serviceTypeId": ["Указанный тип услуги не существует в справочнике."]
  }
}
```

---

### 3.4. `PATCH /api/appeals/{id}/assignee` — Назначение исполнителя
Выполняется заместителем декана отдельным изолированным действием. Статус обращения при этом **не изменяется**.

**Пример тела запроса:**
```json
{
  "assigneeUserId": 3
}
```

**Пример успешного ответа (`200 OK`):**
```json
{
  "id": 2,
  "number": "ОБР-2026-0002",
  "assigneeUserId": 3,
  "status": "New",
  "updatedAt": "2026-10-12T12:15:00Z"
}
```

**Возможные ошибки:**
* `400 Bad Request` — указанный `assigneeUserId` не существует либо пользователь не имеет роли сотрудника деканата (`Staff`).
* `404 Not Found` — обращение с данным `id` не найдено.

---

### 3.5. `PATCH /api/appeals/{id}/status` — Смена статуса жизненного цикла
Выполняется назначенным сотрудником деканата (перевод в `InProgress`, `Closed`) либо заместителем декана (перевод в `Cancelled`).

**Пример тела запроса (Взятие в работу):**
```json
{
  "status": "InProgress"
}
```

**Пример успешного ответа (`200 OK`):**
```json
{
  "id": 2,
  "number": "ОБР-2026-0002",
  "status": "InProgress",
  "assigneeUserId": 3,
  "updatedAt": "2026-10-12T12:20:00Z"
}
```

**Возможные ошибки:**
* `400 Bad Request` — передано неизвестное значение статуса (не входит в перечень `New`, `InProgress`, `Closed`, `Cancelled`).
* `404 Not Found` — обращение не найдено.
* `409 Conflict` — недопустимый переход по графу состояний (например, попытка перевести из `Closed` обратно в `New`) либо попытка смены статуса пользователем, который не назначен исполнителем.
